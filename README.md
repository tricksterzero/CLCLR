# CLCLR

Windows 用のクリップボード履歴マネージャです。コピーしたテキスト・画像・ファイルの一覧を履歴として残し、ホットキーで出すメニューやビューアから、いつでも貼り付け直せます。

CLCL（Ohno Tomoaki 氏、MIT ライセンス。[公式サイト](https://nakka.com/soft/clcl/)・[GitHub リポジトリ](https://github.com/nakkag/CLCL)）の機能と使い勝手を手本に、Rust で作り直したものです。CLCL のソースを移植したものではなく、設計は新しく起こしています。本家との違いは「[本家 CLCL との違い](#本家-clcl-との違い)」にまとめました。

作者は CLCLR を **クルクルル**（ku-ru-ku-ru-ru）と呼んでいます。

## 動作環境

- Windows 10 / 11（64 ビット）を想定しています。動作を確かめているのは Windows 11 だけです
- 表示倍率（高 DPI）とモニターごとの倍率の違いに対応しています
- 画面の文字は日本語だけです。ダークモードの配色には対応していません（Windows のシステムの色で描きます）

## インストール

インストーラーはありません。配布の zip には `CLCLR.exe`・`README.md`・`LICENSE`・`THIRD-PARTY-NOTICES.md` が入っています。展開して、`CLCLR.exe` を書き込みできる好きなフォルダに置いて起動します。

- 設定と履歴は、`CLCLR.exe` と同じフォルダに保存されます（ポータブル）。`C:\Program Files` のように、普通の権限では書き込めない場所には置かないでください
- アンインストールは、フォルダごと消すだけです。レジストリは使いません
- Windows の起動と一緒に動かすには、`CLCLR.exe` のショートカットをスタートアップのフォルダ（エクスプローラーのアドレス欄に `shell:startup` と入れると開きます）に置きます
- `CLCLR.exe` にはデジタル署名がありません。ダウンロードしたものを初めて起動するとき、Windows の SmartScreen が警告を出すことがあります

CLCLR を2つ同時に動かすことはできません（別のフォルダに置いたものでも同じです）。2つ目を起動すると、動いている方のビューアが前に出ます。

### セキュリティソフトの誤検出について

CLCLR は、クリップボードの履歴を取って貼り付け直すために、次の機能を使います。キー入力を記録するソフト（キーロガー）と似た動きに見えるため、セキュリティソフトによっては、マルウェアと誤って判定することがあります。

- クリップボードの監視（コピーした内容を履歴に加えるため）
- 低レベルのキーボードフック（Ctrl・Shift・Alt の二度押しを見るため。二度押しを使う設定にしたときだけ使います）
- キー入力の送出（選んだ項目を、元の窓へ自動で貼り付けるため）

CLCLR には、ネットワークに接続する処理はありません。履歴と設定は、`CLCLR.exe` と同じフォルダに保存します。

## 使い方

### 常駐とトレイ

起動すると通知領域（トレイ）にアイコンが出て、クリップボードの変化を見張ります。コピーするたびに、その内容が履歴に加わります。監視をオフにしているときと、形式フィルタ・ウィンドウフィルタで取り込まない設定にした内容は加わりません。

| トレイのアイコンの操作 | 動き |
|---|---|
| 左クリック | ポップアップメニュー（下）をマウスの位置に出す |
| ダブルクリック | ビューアを出す |
| 右クリック | 「ビューアを表示」「クリップボードを監視」（監視のオン・オフ）「終了」のメニュー |

ビューアの「×」で閉じると、トレイに隠れます（終了はしません）。終了はトレイの右クリックの「終了」からです。トレイのアイコンを出さない設定にしているときは、ビューアを閉じると終了します。

### ポップアップメニュー

ホットキー（既定は **Alt+C**）で、今の入力位置の近くにメニューが出ます。

- 上から新しい順に履歴が並びます（既定は20件）。先頭の10件には `1`〜`9`・`0` のアクセスキーが付きます
- ピン留め（下の「[ピン留め](#ピン留め)」）は「ピン留め(&P)」の子メニューにまとまり、フォルダは入れ子の子メニューになります。設定で履歴より上に出すこともできます
- 項目を選ぶと、その内容がクリップボードに入り、元の窓へ自動で貼り付けます。選ぶときに Shift を押していると、貼り付けはしません（クリップボードに入れるだけ）
- 項目にマウスやキーを合わせてしばらく待つと、中身（テキストは既定で1,024文字・20行まで、画像はサムネイル、ファイルは名前の一覧）を小さな窓で見られます

修飾キーの二度押し（Ctrl・Shift・Alt をそれぞれ素早く2回）に、メニューやビューアを割り当てることもできます（既定ではどれも無効）。メニューは「履歴とピン留め」「ピン留めのみ」「履歴のみ」から選べます。

### ビューア

履歴とピン留めを一覧で見て、操作する窓です。左がツリー（「履歴」とその階層表示のフォルダ、「ピン留め」とそのフォルダ）、右上が一覧、右下がプレビューです。境目はドラッグで動かせます。

| 操作 | 動き |
|---|---|
| Enter・ダブルクリック | 選んだ項目をクリップボードへ送る（貼り付けはしない） |
| Delete | 選んだ項目を消す |
| F2 | ピン留めの項目の名前を変える |
| Ctrl+F | 検索欄へ移る |
| 右クリック（Shift+F10） | 項目のメニュー（下） |

一覧の項目を右クリックしたときのメニューには、次のものがあります（項目の種類によって出るものが変わります）。

- クリップボードへ送る
- ピン留めに追加（履歴の項目。フォルダがあれば、入れる先を選ぶ）／移動・名前の変更（ピン留めの項目）
- 画像を関連付けで開く／画像を書き出してフォルダで表示（画像の項目。一時フォルダ `%TEMP%\CLCLR` に書き出した写しを使うので、編集しても履歴は変わりません）
- テキスト変換（テキストの項目。下の「[テキスト変換](#テキスト変換)」）
- 削除

検索欄に文字を入れると、名前とテキストの全文で一覧を絞り込みます。履歴を表示しているときは履歴の全部から、ピン留めを表示しているときはピン留めの全部から探します。

メニューバーの「ツール」には、設定・履歴のクリア・クリップボードのクリア・データのチェック・最前面に表示があります。

### ピン留め

よく使う内容を、履歴とは別に残しておく場所です（本家の「登録アイテム」にあたります）。履歴の項目を「ピン留めに追加」すると写しが作られるので、履歴が押し出されたり消えたりしても残ります。

- ツリーの「ピン留め」を右クリックするとフォルダを作れます。フォルダを右クリックすると、その中へのフォルダの作成・名前の変更・削除ができます
- ピン留めの項目には名前を付けられます（F2 か右クリックの「名前の変更」）。名前を空にすると、テキストの1行目に戻ります。画像のように本文のない項目に名前を付けておくと、メニューで見分けやすくなります
- 設定で、ピン留めの項目を送るときに `%d`・`%t` を今日の日付・今の時刻に置き換えられます

### テキスト変換

テキストの項目を右クリックして「テキスト変換」を選ぶと、変換した結果をクリップボードへ送ります。元の項目は変わりません。結果は、ふつうのコピーと同じく監視で取り込まれ、新しい履歴として加わります。

- 小文字に変換／大文字に変換
- 引用（各行の頭に引用符を付ける）／引用解除
- テキスト整形（決めた幅で折り返す）
- テキストの挟み込み（前後に決めた文字列を付ける）
- 改行の除去

引用符・折り返しの幅・挟み込む文字列は設定で変えられます。

### データのチェック

「ツール」→「データのチェック」で、保存したファイルの食い違いを調べます。見つけるのは次の3つです。

- `blobs\` の中で、どこからも使われていないデータのファイル
- データのファイルが無くなった項目
- 書き込みの途中で残った一時ファイル（`blobs\` の中の一時ファイルと、`history.toml.tmp`・`pinned.toml.tmp`）

見つかったものは、確かめたうえで消せます。CLCLR が作る名前の形でないファイルは、見つけても消しません。調べるのはファイルの有無と参照だけで、中身の破損までは調べません。

## 設定

「ツール」→「設定」で開きます。「OK」で保存し、その場で反映します（いくつかの項目は次の起動から効きます。画面に書いてあります）。

| タブ | 主な項目 |
|---|---|
| 全般 | クリップボードの監視、トレイのアイコン、起動時にビューアを出さない、起動時のクリップボードの同期、操作の失敗の知らせ |
| 履歴 | 最大件数（既定 30、0 は無制限。階層表示を使うときは、階層表示の件数が上限になる）、古い履歴をフォルダにまとめる（階層表示）、重複のチェック、保存のしかた、送った内容を履歴に加えない、追加の音 |
| ホットキー | メニューのホットキー、自動の貼り付け、メニューに出す履歴の件数、ピン留めを上に出す、ツールチップ、修飾キーの二度押し |
| テキスト変換 | 引用符、折り返しの幅、挟み込む文字列、改行の除去のしかた、日時の置き換え |
| 形式フィルタ | 取り込むクリップボードの形式、保存するか、大きさの上限。既定で取り込むのはテキスト（CF_UNICODETEXT）・画像（CF_DIB）・ファイル（CF_HDROP） |
| ウィンドウフィルタ | コピー元の窓（タイトル・クラス名）で、取り込まない窓を決める |

履歴のデータの本体（`blobs\`）は、取り込んだときに書きます。履歴の一覧（`history.toml`）は、既定では終了のときにまとめて書きます（削除などで一覧が変わったときも書きます）。「変更の都度履歴を保存する」をオンにすると、取り込むたびに一覧も書きます。「終了時に履歴を保存する」と両方をオフにすると、履歴をファイルに書かない完全メモリモードになります（ピン留めはいつも保存します）。

設定は `config.toml`（TOML 形式のテキストファイル）に保存されるので、手で直すこともできます。直すときは CLCLR を終了してからにしてください。

## データの置き場所

どれも `CLCLR.exe` と同じフォルダです。

| ファイル | 中身 |
|---|---|
| `config.toml` | 設定 |
| `history.toml` | 履歴の一覧（名前・日時・形式など） |
| `pinned.toml` | ピン留めの一覧とフォルダ |
| `blobs\` | 履歴とピン留めのデータの本体。画像は WebP（可逆圧縮）で保存します |
| `panic.log` | 予期しないエラーで止まったときの記録（起きたときだけ作られます） |

バックアップや別の PC への引っ越しは、CLCLR を終了してから、このフォルダごとコピーしてください。

## 本家 CLCL との違い

CLCLR は、CLCL の使い方（Alt+C のメニュー、ビューア、登録アイテム、テキスト変換、フィルタ）を保ったまま作り直すことを目指しています。本家のソースを移植したものではないので、中の作りは別物です。

### 変わったところ

- **exe 1つで動く**: 本家は `CLCL.exe`・`CLCLHook.dll`・`CLCLSet.exe`（とプラグインの DLL）の組ですが、CLCLR は `CLCLR.exe` 1つです。設定画面も本体にあります。64 ビットのネイティブの exe です
- **キーフックの DLL を使わない**: 本家はキーボードのフックに DLL（`CLCLHook.dll`）を使いますが、CLCLR は自分のプロセスの中の低レベルのキーボードフック（`WH_KEYBOARD_LL`）で修飾キーの二度押しを見ます。二度押しを使う設定のときだけフックを張ります
- **設定と履歴の一覧はテキストファイル**: 本家の `clcl.ini`・`history.dat`（独自のバイナリ形式）に代わって、TOML 形式のテキストファイルに保存します
- **画像を圧縮して保存する**: 画像は WebP の可逆圧縮で保存します。画面のスクリーンショットのような画像では、ファイルがずっと小さくなります（下の実測）
- **保存先はいつも exe の隣**: 本家は既定では `%LOCALAPPDATA%\CLCL` に保存し、ポータブルにする設定があります。CLCLR はいつもポータブルです

本家のプラグインのうち、テキスト変換（tool_text）、履歴の階層表示（tool_history）、履歴のクリアや最前面などの便利機能（tool_utl）にあたるものは、本体に入っています。プラグインの仕組みそのものはありません。履歴の階層表示は一覧の見せ方を変えるだけで、保存している履歴は組み替えません。

細かなところでは、ビューアの検索が、入れた文字で一覧をその場で絞り込む形になっています（名前とテキストの全文が対象）。テキスト変換は元の項目を変えず、結果が新しい履歴になります。メニューのツールチップには、テキストと画像のサムネイルを並べて出します。

### 実測

どれも、同じ PC（Windows 11）で、同じ測り方で測った1つの例です。環境によって変わります。

| 項目 | CLCLR | 本家 CLCL 2.1.3（32 ビット） | 条件 |
|---|---|---|---|
| 常駐のメモリ（ワーキングセット） | 約 17.4MB | 約 14.7MB | 履歴が空、ビューアを出さずに常駐、起動から60秒後。5回の中央値（2026-09-27） |
| 常駐のメモリ（プライベート） | 約 5.5MB | 約 4.5MB | 同上 |
| 本体の大きさ | 約 2.0MB（`CLCLR.exe` 1つ） | 約 1.2MB（`CLCL.exe`・`CLCLHook.dll`・`CLCLSet.exe` の合計） | CLCLR 1.0.0 と本家 2.1.3 |
| 画像25件を保存したときの大きさ | 約 22MB | 約 206MB | 1920×1080 の、画面のような模様（文字のような細かい点を含む）の合成画像（2026-09-27） |

常駐のメモリは本家よりわずかに多く、「本家より軽い」とは言えません。画像を保存したときの大きさの差は、圧縮の効きやすい画像での例です。写真のような画像では、差はずっと小さくなるはずです（実測していません）。

### 開発言語による違い

本家は C 言語、CLCLR は Rust で書かれています。Rust は、C で起きやすいメモリの扱いの誤り（使い終わったメモリをまた使う、決めた範囲の外を読み書きする、など）を、作る段階や動いている間に見つけて防ぐ仕組みを持つ言語です。そのため、そうした誤りで動きがおかしくなったり、データが壊れたりすることが起きにくくなっています。ただし、Windows の機能を直に呼ぶ部分はこの仕組みの外にあり、そこは人が確かめています。

予期しないエラーで処理が止まったときは、`panic.log` に記録が残ります。

もっと詳しい説明は「[開発者向けの補足](#開発者向けの補足)」にあります。

### 本家にあって CLCLR に無いもの

- プラグイン（ツール・形式の DLL）の仕組み
- ビューアでの項目の中身の編集、ドラッグ＆ドロップ、複数の項目をまとめての操作（複数を選んでも先頭の1つだけが対象）
- クリップボードの形式のバイナリ表示、画像の PNG・JPEG での保存（CLCLR の画像の書き出しは WebP か BMP）
- RTF・メタファイルなどの形式の表示（本家では形式のプラグインを足すと表示できる）
- 登録アイテムごとのホットキー、窓ごとのコピー・貼り付けのキーの設定、メニューの表示の書式、コマンドラインの引数
- 英語の画面
- ビューアの位置の保存（大きさは保存します）

### データの互換性

本家の履歴（`history.dat`）・登録アイテム・設定（`clcl.ini`）は読み込めません。CLCLR は空の履歴から始まります。本家と同時に動かすときは、ホットキー（Alt+C は先に起動した方が使います）と二度押しが重ならないように、どちらかの設定を変えてください。

## 既知の制限

- ダークモードの配色、読み上げソフト・ハイコントラストへの対応は考えていません
- 画面の文字は日本語だけです
- Windows 10 では動作を確かめていません
- 設定画面の大きさは固定です。縦の解像度が小さい画面で表示倍率を大きくすると、設定画面の上下が画面からはみ出します（1920×1080 のモニターでは、175% 以上ではみ出すことを確かめています）

## ソースからのビルド

Rust（edition 2024 に対応した版。開発では 1.98.1 を使っています）と、MSVC のツールチェーン（Visual Studio の C++ ビルドツールと Windows SDK。exe のリソースのコンパイルに使います）が要ります。

```powershell
cargo build --release   # target\release\CLCLR.exe ができる
cargo test              # 自動テスト（ポップアップメニューが一瞬出るテストを含む）
```

配布用の zip は `scripts\release.ps1` で作ります。テストと release のビルドを通した後、`target\dist\` に zip と、リリースのページの文面（[CHANGELOG.md](CHANGELOG.md) のその版の節と SHA-256）を作ります。GitHub へのリリースは行わず、実行するコマンドを表示するだけです。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\release.ps1
```

## 開発者向けの補足

### 開発言語（Rust）について

本家は C 言語で書かれ、Visual Studio でビルドする 32 ビットの exe です。CLCLR は Rust で書き、Win32 API は `windows` クレートを通して直に呼んでいます。言語が違うことで、次の違いがあります。

- **メモリの扱いが安全**: Rust では、`unsafe` と書いた部分の外で、解放したメモリを使うことと、スレッドの間で同じデータを同時に書き換えること（データ競合）を、コンパイラが許しません。配列の範囲の外の読み書きは実行のときに確かめられ、当たると黙ってメモリを壊すのではなく、その処理を止めます（パニック）。止まった場所は `panic.log` に書き、履歴の操作の途中で止まったときは、壊れているかもしれない状態を書かないように、以後の変更と保存を断ります。CLCLR は、クリップボードの監視・ホットキー・トレイ・ビューアの操作・検索・画像の読み込みを別々のスレッドで動かしているので、この仕組みが効く所が多くあります。ただし、Win32 API を呼ぶ所は `unsafe` で書く必要があり（テストを除くと、`unsafe` の語を含む行が約 290 行）、そこの正しさはコンパイラではなく人が確かめています
  - 補足（整数の桁あふれ）: 整数の桁あふれは、言語任せにしていません。release のビルドでは、Rust も整数の桁あふれを検査しません（黙って回り込みます）。そのため、ほかのアプリがクリップボードに置いた画像のヘッダーのような外から来る値の計算は、桁あふれを確かめる演算で書いています
- **ライブラリ（クレート）に任せる所がある**: TOML の読み書き、WebP の圧縮と展開、UUID の生成などは、広く使われている Rust のクレートを使っています（[THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)）
- **自動テスト**: Rust の標準のテストの仕組み（`cargo test`）で、機能ごとに必要な自動テストを書いています。窓・メニュー・クリップボードを実際に使うテストも含みます

「[実測](#実測)」の差（exe の大きさと常駐のメモリ）には、言語の違いのほかに、64 ビットと 32 ビットの違い、組み込んでいるクレート、機能の違いが混ざっています。言語だけによる差は切り分けていません。
